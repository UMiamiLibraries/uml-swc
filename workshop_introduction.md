## University of Miami Carpentries Workshop Launch Guidelines

Some ideas of how to launch a workshop

### Welcome to a Carpetnries workshop
1. Introduce yourself
2. Introduce the carpentries
  - global organization dedicated to "... equipping individuals with essential data and computational skills ... [and] promote efficient, open, and reproducible research practices ... [to] build an inclusive network of practitioners and advocates who emphasise the critical role of software and data in advancing research ..."
  - open, inclusive, lifeong learning, community, diversity ...
  - started 1998 based on open collaboratively built lessons for computing ... collaborative lessons are still a pillar of SWC community and available to all for use in teaching
  - live coding as a teaching methods
     - everyone comes along for the ride
     - we go as slow as the slowest in the room
     - help your neighbors if you finish early
     - we are here to learn together
     - mistakes are to be celebrated and shared
     - group debugging is a research skill
  - code of conduct and incident reporting (show links in web page and etherpad)
  - _tell a story about your experience with the carpentries !!!_

### Get to know each other
3. Have any other instructors and helpers introduce themselves
4. If time allows, go around the room with an icebreaker ...
   - your name, your department, what you want to learn, and ... ( something fun )

### Workshop Logistics
5. Introduce the carpentries intensive learning style
   - introduce library workshops as an comlimentary alternative
   - introduce other learnign resources and people at UM
6. Schedule and outline (use workshop webpage)
   - get everyone to open workshop webpage
   - have everyone go to the shared etherpad
   - have everyone open the git/bash lesson
7. Breaks and stuff, lunch plans, bathrooms, etc

### Why are we here (learning scenarios)?
8. If time permits, ask about jargon people know or don't know
   - this can also be done in the etherpad ....
9. If time permits, talk about "The Mother of all Demos"
10. Introduce the data management problem ...
   - we have a repetetive task that excel can't do
   - we are dealing with data that can't be opened in "office" applications
   - we want to make graphics
   - we want to ...
11. Code as a solution but ... can code double click to open a file?
   - need to learn to navigate (bash/shell)
   - need to learn basic code syntqax (loops, opening, saving, etc)
   - need to manage working with code (and data) in groups (git)

_Without all three of these fundamental skills -- shell, git, and code syntax -- we cannot follw best practices for data science. Combining these pillars of data management is the Carpentries' way of enabling researchers to be more productive._
